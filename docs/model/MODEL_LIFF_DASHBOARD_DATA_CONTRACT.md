# Model LIFF + Model Dashboard Data Contract

Status: source contract only. No deploy from this document.

## Decision

Use one canonical model-safe aggregate layer, then project it differently:

- Model LIFF = compact, action-first, current-context surface.
- Model Dashboard = broader model relationship and performance surface.

Do not duplicate logic between LIFF and dashboard. Both must read from verified source tables or the worker-owned snapshot table.

## Model LIFF projection

LIFF should stay light. It is for a model checking or acting on the current context in LINE.

Allowed in LIFF:

- current active job/session state
- allowed session actions
- short model profile label
- safe status chips such as `confirmed`, `arrived`, `work_finished`
- compact rating badge only when `review_rating_verified=true` and `review_model_visible=true`
- one short `liff_summary_th` if `model_visible_liff=true`
- pending review/action notices such as media review pending or rate request pending

Do not show in LIFF by default:

- 12-month earnings table
- full payout statement
- customer names, LINE IDs, phones, exact private locations, or notes
- raw review text unless already redacted into `review_model_visible_text`
- private flash URLs, raw R2 keys, Drive IDs, payment refs, bank/slip data
- internal model ability notes, GWs/EMs reveal policy internals, private tier logic, MMD margin, commission logic

Rationale: LIFF should reduce friction during work, not become a financial/admin console.

## Model Dashboard projection

Model Dashboard may show the broader safe model view.

Allowed in Model Dashboard:

- 12-month verified payout total from `verified_payout_12m_thb`
- monthly/period payout summaries generated from `Payout Evidence`
- completed job count
- verified average rating and verified review count
- redacted model-visible review snippets
- profile refresh or check-in signal, phrased neutrally
- rate/media/gallery/private-flash request status
- model-safe referral reward statement when the referral reward ledger is verified

Still forbidden in Model Dashboard:

- customer identity and raw contact data
- bank/slip URLs, payment refs, raw payment evidence, provider transaction IDs
- MMD revenue, MMD margin, customer spend, commission internals
- internal risk flags, service ability private notes, SIGIL classification internals
- raw LINE notes, LINE group names, album/slip evidence, Drive/R2 internal keys

## Neutral signal wording

Signals must never accuse the model or diagnose a personal issue.

Use neutral labels:

- `normal`
- `watch`
- `action`
- `inactive_check`
- `profile_refresh_candidate`
- `service_checkin_recommended`

Do not use labels such as `bad_model`, `problem_model`, `low_quality`, or blame-oriented copy.

## Rating normalization

Only numeric customer ratings may create stars:

- 10/10 -> 5.0
- 9/10 -> 4.5
- 8/10 -> 4.0
- 5/5 -> 5.0
- 4/5 -> 4.0

Qualitative-only feedback such as `ดีมาก` must stay as text evidence and must not generate a fabricated star rating.
