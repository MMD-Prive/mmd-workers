## Source findings and fixes

- #2446 placed completeness request dispatch inside `scheduled()`, where
  `request` is undefined, and omitted it from `fetch()`. Move dispatch into fetch;
  keep scheduled jobs free of request routing. This is a release-blocking source
  regression found by inspection, not an observed production incident.
- Membership `nextAction` is lifecycle navigation, not a general action queue.
  Historical payment history explicitly cannot establish a current unpaid bill.
- Reuse `/v1/member/payments` for current session-bound canonical payment URLs,
  `/api/member/app/session/current` for one owned upcoming booking, and the
  existing canonical membership projection for the expired-member renewal CTA.
  The attention reader calls the existing base Worker so entitlement decorators
  and its fail-closed checks remain in effect. Browser identity selectors are rejected.
- CARE BACK already owns redemption, release, expiry rejection, owner checks and
  same-session replay logic. No new coupon issue/redeem/payment authority is added.
  Its Airtable write-and-reread is **not a concurrency proof**; that financial
  lifecycle is unchanged by this patch.
- Missing wallet fields now return `checking`, rather than an empty coupon list.
  Both ordinary and recovery coupon projections suppress expired navigation.
  Current benefits and collapsed used/expired history are separate in Webflow.

## Prepared interfaces

- `GET /api/member/app/attention`: session-gated, no-store, navigation only.
  Payments take priority; an existing pending/review payment suppresses another
  renewal CTA. An unreadable payment source also suppresses renewal. Booking
  navigation opens the exact session in Webflow's booking detail view. Its confirm
  button appears only when the existing session API permits acknowledgement and
  submits only the session reference to the existing `/api/member/app/session/ack`.
  A response must read back the same session and its acknowledgement timestamp.
  Double click is disabled; an ambiguous failure requires a fresh read before retry.
- Webflow Home displays at most three tasks; attention errors preserve the member
  snapshot and news. Partial source coverage never says all tasks are cleared.
- `GET /v1/admin/my-mmd/operations`: credential-bound owner-only read projection.
  Groups: loaded payment review rows (currently up to six), structural member
  review rows, overdue coupon-watch decision classes, renewal join unavailable,
  and all CMS draft pages. Every numeric count equals displayed rows; scopes are
  explicit and unavailable counts are null. Coupon decision classes also expose
  their separate affected-case count. No claim of global queue totals.
- Admin module mounts inside `#my-mmd-management`, with loading/error/owner gate,
  checked time, collapsed groups, direct navigation and batches of ten display rows.
- CMS draft reads use server-only `WEBFLOW_CMS_TOKEN` in the **admin-worker** too.
  No token was created, transferred, configured or printed by this work.
