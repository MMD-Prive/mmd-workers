# Payments/Points canonical identity: first cleanup slice

The production `payments-worker/wrangler.merged.toml` entrypoint is `index.review-wrapper.js`, which calls `awardBasePointsPhase1`. Previously its email lookup selected the first Members row and used `member_id || Member ID || memberstack_id` as a coordinator/ledger key. A legacy-only or ambiguous match could therefore post points under a noncanonical identity.

This slice accepts only nonempty string canonical `member_id` / `Member ID` values. Matching aliases are allowed; conflicting aliases or nonstring values are rejected. An email lookup must identify exactly one Members record across the three supported email aliases, with one canonical ID. More than one row, pagination, disagreement across aliases, legacy-only rows, incomplete responses and read failures return `canonical_member_id_required` without coordinator dispatch or ledger writes. Only Airtable's explicit 422 unknown-field schema rejection allows checking the next email alias.

A supplied canonical ID without email keeps the existing trusted internal path. If email is supplied, its lookup must agree with that ID. A direct coordinator payload must also have an unambiguous canonical string. A replay whose existing ledger belongs to a different canonical identity is rejected without another write; a same-member replay retains its existing duplicate receipt.

Compatibility impact: legacy-only callers/records will skip the points award; supplied-ID requests with invalid, unavailable, missing or conflicting email matches will also skip. A verified payment is not reversed by this change: the wrapper retains the payment result and exposes the guarded `points_ledger` outcome for follow-up. A historical replay with missing/conflicting ledger identity can now fail closed rather than returning a misleading successful duplicate result. No balances, historical fields, payments, credentials, grants or data migrations are changed. The 100 THB rate, eligible stages, remainder carry, payment-ref idempotency key and 365-day lot expiry are unchanged.

Before release, separately verify read-only coverage of the configured Members table: canonical field availability, legacy-only/blank canonical IDs, conflicting aliases, duplicate/shared email matches across all supported aliases, and reviewed payment callers that send both ID and email. Also review historical duplicate ledger identity coverage. This task does not certify population-wide coverage or migrate records; it tests the production writer boundary using fixtures. Legacy-ID assignment, Booking/Auth/Admin cleanup and any balance repair remain separate reviewed slices.

Validation: focused identity/writer tests plus root `npm test` under Node 22, existing Points Phase 1 CI and production payments configuration Wrangler dry-run. The points tests are now included in root `test:payments-unified` as well as the existing dedicated workflow. Draft only; no merge or deploy authorized by this task.
