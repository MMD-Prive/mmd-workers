# APP × SIGIL Release Gate — 2026-09-29

Owner sequence:

```text
Performance / route stability
-> Production smoke
-> SIGIL Search with real approved public-safe Model media
-> genuine LINE / LIFF role acceptance
-> Always-on APP campaign
```

## Current release rule

**Campaign remains HOLD until every mandatory gate below has evidence.**

### Gate A — Production app routes
Require read-only production proof that:
- MY MMD opens from the canonical customer route;
- MMD APP opens from the canonical Model LIFF route;
- role separation is preserved;
- no horizontal overflow or shell fallback regression blocks normal use.

### Gate B — Customer identity / history
Require one genuine customer chain:
- LINE identity resolved;
- customer opens MY MMD;
- canonical member/client history is read from backend authority;
- Points/history/request surfaces do not invent missing data.

### Gate C — Model identity
Require one genuine Model chain:
- LINE Verify;
- existing-bound or verified-new resolution;
- dashboard opens with canonical Model identity;
- no customer entitlement is used as Model authority.

### Gate D — SIGIL Search media
Require at least one real search result whose visible media is:
- linked to the canonical Model;
- active;
- approved;
- public-safe;
- served through the canonical media policy.

Fixtures and unlinked media do not close this gate.

### Gate E — Search failure safety
Production/search acceptance must still fail closed when:
- media is missing;
- media approval is revoked;
- API returns no eligible Models;
- a requested protected category is not available to the viewer.

### Gate F — Campaign launch
Only after A–E pass:
- launch destination is the current canonical APP/MY MMD route;
- ad copy does not promise data/features that are still staged;
- monitor first-day failures before increasing spend.

## Evidence record

For every passed gate capture:
- observed Bangkok timestamp;
- route / workflow run;
- safe internal reference;
- what passed;
- what remains unproven.

Never paste LINE user IDs, tokens, cookies, payment proofs, or private media into the PR.
